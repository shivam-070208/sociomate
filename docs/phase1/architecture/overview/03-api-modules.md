# API Modules

## Overview

The API is organized into business-domain modules rather than technical layers. Each module owns a specific domain, exposes REST endpoints, contains its own business logic, and communicates with other modules through well-defined interfaces.

This modular architecture improves maintainability, scalability, and separation of concerns while allowing each domain to evolve independently.

---

## Responsibilities

* User registration

* User logout
* Session management
* JWT/API token validation
* OAuth authentication
* Password management

# Providers

## Purpose

Provides a unified abstraction for all supported social platforms.

## Responsibilities

* Route provider-specific requests
* Execute provider operations
* Normalize provider responses
* Handle provider capabilities
* Manage provider configuration

The Provider module acts as a bridge between the platform and external social media APIs.

# Content

## Purpose

Represents platform-independent content that can be published through different providers.

## Responsibilities

* Create content
* Edit content
* Manage drafts
* Attach assets
* Validate platform compatibility
* Generate previews

The Content module abstracts platform-specific concepts such as posts, messages, stories, and broadcasts into a unified model.

---

# Executions

## Purpose

Represents the execution engine of the platform.

Every long-running operation is represented as an Execution.

## Responsibilities

* Create executions
* Track execution status
* Manage execution steps
* Retry failed executions
* Cancel executions
* Store execution logs
* Generate execution timeline
* Publish execution events

This module is the core of the platform.

# Core Principles

* Every module owns a single business domain.
* Modules communicate through well-defined interfaces.
* Long-running operations are delegated to the Execution Engine.
* Provider-specific logic remains isolated from core business logic.
* Every module should be independently maintainable and extensible.
* Cross-module communication should avoid tight coupling.
